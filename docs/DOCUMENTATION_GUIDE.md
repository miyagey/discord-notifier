# 📋 AIドキュメントメンテナンス & 開発自動化指示書

## 1. 目的と運用方針

本指示書は、`miyagey/discord-notifier` リポジトリにおける **ドキュメント更新・コード修正・設計維持を AI アシスタントへ自動委譲するための運用ルール** を定義する。

AI は作業を実施する際、本指示書および `AGENTS.md` に定められた規範を厳格に遵守し、責務の逸脱や誤った自動生成（ハルシネーション）を防止しなければならない。

---

## 2. ドキュメントの配置と役割分担（維持管理ルール）

リポジトリ内のドキュメントは以下の 4 層構造とし、AI は更新内容に応じて適切なファイルを選択して編集すること。

```text
.
├── README.md                 # 1. 開発者ガイド (セットアップ・コマンド・オンボーディング)
├── AGENTS.md                 # 2. AIエージェント用行動規範 & プロンプト制約
└── docs/
    ├── ARCHITECTURE.md       # 3. アーキテクチャ & モジュール構造設計書
    ├── SYSTEM_SPEC.md        # 4. システム機能 & データ構造仕様書
    └── FORM_SPEC.md          # 5. フォーム連携仕様書 (※非推奨・廃止予定)
```

### 📄 ファイル別編集ルール

* **`README.md`**: 環境構築・`clasp` / `npm` コマンド・CI/CD 設定など、人間がオンボーディング時に必要な情報のみを記述する。機能やモジュール構造の詳細を直接書かず、`docs/*` への参照リンクを貼る。
* **`AGENTS.md`**: AI コーディング時に絶対遵守すべき「行動指針・制約ルール」のみを命令形で記述する。
* **`docs/ARCHITECTURE.md`**: プログラム（GAS）の層構造、レイヤー間依存関係、DTO パターン、エラーハンドリング方針を記述する。
* **`docs/SYSTEM_SPEC.md`**: 機能概要、データモデル（スプレッドシート定義）、通知・自動同期のデータフロー仕様を記述する。
* **`docs/FORM_SPEC.md`**: Google フォーム連携に関する仕様を隔離・記述する（新規機能追加は行わない）。

## 3. Mermaid 図の描き分け・更新基準

AI がドキュメント内の Mermaid 図を作成・更新する場合は、以下の基準に従い交差のないクリアな図を生成すること。

1. **交差・折れ曲がりの最小化**:
   * データ・モジュール層を 3 階層（入力/UI ➔ バックエンド/処理 ➔ 外部連携/DB）に明確化する。
   * 矢印ラベルに処理順序を示す「数字（1., 2.等）」を付与せず、データ通信の内容のみを記述する。

2. **`docs/SYSTEM_SPEC.md` 用（機能・データフロー図）**:
   * 内部コード名（`SheetService` や `Orchestrator` 等）には踏み込まず、ユーザー操作・データストア（シート）・外部通知（Discord/カレンダー）の機能的繋がりを描画する。

3. **`docs/ARCHITECTURE.md` 用（モジュール・レイヤー構造図）**:
   * `spreadsheet/` 配下のファイル構造（`Webアプリ.js`, `定期通知バッチ.js`, `SheetService`, `DiscordService`, `CalendarService`）に対応する層構造と依存関係（呼び出し方向）を明示する。

## 4. 作業実行フロー（AI への指示手順）

今後 AI にドキュメント改修や更新を行わせる際は、以下のプロンプトテンプレートを用いて作業を提示してください。

```text
【指示内容】
本リポジトリの docs/ARCHITECTURE.md および docs/SYSTEM_SPEC.md を最新の設計方針に基づいて更新してください。

【実行要件】
1. AGENTS.md および docs/ARCHITECTURE.md に記述された最新のレイヤー構造・設計ルールを反映すること。
2. Mermaid 図は、SYSTEM_SPEC (機能データフロー) と ARCHITECTURE (モジュール依存関係) で観点を明確に描き分け、線の交差がない配置にすること。
3. 定期通知バッチの改修方針（アーリーリターン廃止、一本道フロー）に沿った説明文に修正すること。
```
